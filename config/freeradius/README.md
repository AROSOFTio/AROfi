AROFi production FreeRADIUS foundation

- `mods-available/sql` enables PostgreSQL-backed authorization, session checks, accounting, and post-auth logging.
- `radcheck`, `radreply`, `radacct`, `radpostauth`, and `nas` are created by Prisma migrations.
- SQL client loading is enabled with `read_clients = yes`; tenant MikroTik routers are written to the `nas` table when they are created in AROFi.
- `mods-config/files/authorize` contains only the health-check user. Customer vouchers and paid packages must be provisioned by the API into SQL.
- MikroTik HotSpot should send `Calling-Station-Id` for audit visibility. Paid-package RADIUS auth uses the generated username/password and package timeout.

Deployment notes:

- Update `RADIUS_PUBLIC_HOST` in `docker-compose.yml` or `.env` so MikroTik routers point at the reachable VPS IP or hostname.
- `clients.conf` intentionally contains only local/dev clients. Production MikroTik NAS clients must come from the SQL `nas` table.
- Keep the router-specific shared secret aligned between the RouterOS onboarding script and the `nas.secret` value generated by the API.
- FreeRADIUS SQL client behavior can be deployment/version dependent. If a newly created router is still rejected as an unknown client, run a controlled FreeRADIUS reload/restart after the router is created and confirm the `nas` row is present.
- Enable accounting and interim updates on the MikroTik HotSpot profile.
- HotSpot `shared-users=1` reduces sharing. NAT tethering cannot be guaranteed to be detectable in every case by a captive portal platform alone.
